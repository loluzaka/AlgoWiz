Okay so first rereading the arch doc, the "algorithms are recorders" conept where they run, store every moment into a `vector<Step>`, and the engine just plays it back. Preparing the header files for the same.
On "delta": a delta is just the change between two states, instead of storing the global state at every step (a full snapshot), we store only what changed, like previous and new values. So each `Step` should carry the diff (what field changed, old value, new value) rather than a copy of the entire data structure.

11:14
DECISION: Step stores a sequence frame + delta model, not full snapshots.

Options I considered:
  a) keep full snapshots. Simple to render, but memory explodes and it
     contradicts the doc.
  b) pure deltas, no snapshots. Memory tiny, but stepping backward means
     replaying from step 0 every time. Terrible.
  c) keyframes every K steps + deltas in between. Memory bounded by K
     and by number of keyframes, rewind cost bounded by K.

going with (c): keyframes every K steps plus deltas in between — bounded memory, rewind cost capped at K, and it's the standard undo-timeline pattern.

also, for going bac, deltas only need to replay forward from the nearest keyframe, so they don't have to be self-sufficient — much simpler contract to write
